План отражает оставшиеся вопросы. Статус сценария меняется на `VERIFIED_RUNTIME` после наблюдения в игре и записи исходного состояния, действий и фактического результата. Штатные прохождения ниже остаются `RUNTIME_PENDING` в [[../SANTA_MONICA_RESEARCH_COMPLETION|приёмке]].

**Наблюдение 16.11.2026, `VERIFIED_RUNTIME` для прямой загрузки.** Windows, отдельная копия UP 12.0 с user.cfg, выбирающим Plus. Запуски `Vampire.exe -game Unofficial_Patch -windowed -w 1024 -h 768 -console -condebug +map <имя>` проверили `sm_pawnshop_1` и `sm_vamparena` без загрузки старых сохранений (для арены также передавались `-novid` и диагностический cfg с клавишами). После загрузки в убежище виден интерьер, HUD и субтитры радио; в Foxy Boxes видны HUD и входной коридор. Скрипт копии обновил `haven_pc.txt`, а эталон сохранил исходный SHA. Обе проверки ограничены загрузкой и появлением игрока. Штатные переходы, бой и квестовые результаты остаются открытыми.

**Прогон 17.11.2026.** На отдельной копии терминальный доступ через `agent-desktop` доставил клавишу к окну игры и чтение файла подтвердило импорт установленного Plus-модуля. Диагностический таймер не запустился из-за `NameError` на старте Python. Результата штатного перехода нет. Копия закрыта, экспериментальные изменения скриптов восстановлены из эталона, SHA проверены.

**Диагностика касания Pier 17.11.2026.** Запущено одно окно копии. Целевой cfg должен был загрузить Pier для записи координат при раскрытии перехода и после высадки. `agent-desktop` подтвердил доставку части клавиш и зафиксировал свёрнутое окно при дальнейшем вводе. ## Запуск и консоль

Использовать отдельную копию игры. По инструкции установленного UP (`Unofficial_Patch/VTMBup-readme.txt:4753`) стартовые ролики Bink отключаются переименованием каталога `Vampire/media`. В рабочей копии он переименован в `media.startup-disabled`, четыре исходных BIK на месте и совпадают по SHA-256 с эталоном. Переименование обратимо. После изменения выполнена файловая проверка.

1. Запускать из корня копии `Vampire.exe -game Unofficial_Patch -windowed -console`. Локальный `Start-UP12-Console.cmd` использует эти параметры. Старт идёт в главное меню; для штатного сценария загрузить подготовленное сохранение через игру.
2. Найти конкретный PID и окно через `agent-desktop list-windows --app Vampire`. Дерево UI Automation здесь показывает только рамку окна. Для клавиш использовать `agent-desktop press --window-id <id> f10` после проверки фокуса. В `autoexec.cfg` копии F10 привязана к `toggleconsole`, F11 — к `exec sm_probe.cfg`. Главное меню подходит для открытия консоли согласно локальному readme. Результат доставки клавиши сверять по выводу команды.
3. Для диагностических команд использовать отдельный `cfg/sm_probe.cfg`. Начальный smoke test содержит `echo SM_RUNTIME_CONSOLE` и `status`. `cmdlist` и `cvarlist` подтверждают команды конкретной версии. SDK ZVTool получает имя карты из модели `worldspawn` в `python/zvtool/zvtool_util.py:getMapName()`; установленный Python читает координаты через `__main__.FindPlayer().GetOrigin()`. Автоматическую запись этих значений из старта ещё предстоит подтвердить. Параметр `-condebug` в последней попытке текстового лога не создал.
4. Для квестового теста начинать с сохранения нужной стадии и пользоваться штатными дверями, предметами и диалогами. `map` нужен только для диагностики конкретного BSP. Старые сохранения из каталога `save/incompatible` сначала проверять отдельно на копии. В эталонные файлы и сохранения запись не требуется.

## Подготовка

Сохранить SHA-256 эталонных конфигураций, нужных BSP и исходных сохранений. Для игры использовать отдельную копию установки и копии сохранений. `vamputil.py:setPlus()` открывает `vdata/hackterminals/haven_pc.txt` на запись и меняет имя в почтовом интерфейсе. Зафиксировать moddir, версию, режим Basic/Plus, клан, журнал, сюжетный этап и наличие ключей. Для альтернативных исходов возвращаться к одному контрольному сохранению. Консольный запуск карты пригоден для проверки геометрии и загрузки, но квестовые условия проверяются по штатному происхождению игрового состояния. Фиксировать команды, если они использовались.
